SISTEMA WEB DE CONTROL DE HORARIOS CON LECTOR DE HUELLAS PARA FARMACIA

Actúa como un Arquitecto de Software, Desarrollador Full Stack Senior, especialista en Python Flask, React, MySQL, seguridad web, sistemas de control de asistencia e integración con lectores biométricos.

Necesito desarrollar un sistema web para una farmacia destinado al:

CONTROL DE HORARIOS DE TRABAJADORES MEDIANTE LECTOR DE HUELLAS DIGITALES.

El sistema debe desarrollarse utilizando:

- Python Flask para backend.
- React + Vite para frontend.
- MySQL para base de datos.
- Lector de huellas digitales para identificación de trabajadores.
- openpyxl para Excel.
- ReportLab para PDF.

El frontend debe ser sencillo, moderno, limpio, responsive y fácil de utilizar.
TODAS las vistas deberán adaptarse correctamente a escritorio, laptop, tablet y móvil.

1. OBJETIVO DEL SISTEMA

El sistema permitirá registrar mediante huella digital:

1. Entrada al trabajo.
2. Salida a almuerzo.
3. Regreso de almuerzo.
4. Salida del trabajo.

Cada marcación deberá registrar automáticamente:

- Trabajador identificado.
- Fecha.
- Hora.
- Tipo de marcación.
- Horario que tenía asignado.
- Estado de puntualidad.
- Minutos de atraso o anticipación.
- Fecha y hora exactas del servidor.

2. HORA OFICIAL DEL SISTEMA

ESTA ES UNA REGLA CRÍTICA.

La hora de una marcación NO será:

- Escrita por el trabajador.
- Seleccionada por el trabajador.
- Enviada desde React.
- Tomada del reloj JavaScript del navegador.
- Modificable desde el frontend.

La hora deberá ser obtenida EXCLUSIVAMENTE en el backend Flask usando la hora del sistema.

Configurar:

America/Guatemala

como zona horaria.

Conceptualmente:

ahora = obtener_hora_actual_guatemala()

Cuando el trabajador coloque la huella:

HUELLA IDENTIFICADA
        ↓
BACKEND OBTIENE HORA DEL SISTEMA
        ↓
BACKEND REGISTRA MARCACIÓN

React nunca deberá mandar algo como:

{
    "hora": "08:00"
}

La API únicamente deberá recibir el tipo de marcación solicitado.

11. HISTORIAL DE HORARIOS

IMPORTANTE:

Si un trabajador tenía:

Entrada: 08:00

durante agosto y el administrador cambia posteriormente su entrada a:

09:00

los registros anteriores NO deben recalcularse utilizando 09:00.

Cada marcación deberá guardar también la hora programada correspondiente a ese momento.

Ejemplo:

Fecha: 15/08/2026

Hora programada: 08:00
Tardanza: 13 minutos

Aunque posteriormente el horario del trabajador sea modificado, ese registro histórico debe permanecer igual.

12. SECUENCIA OBLIGATORIA DE MARCACIONES

ESTA REGLA ES FUNDAMENTAL.

Las marcaciones dependerán unas de otras.

La secuencia válida será:

ENTRADA
   ↓
SALIDA_ALMUERZO
   ↓
REGRESO_ALMUERZO
   ↓
SALIDA

No permitir saltarse pasos.

13. REGLA DE ENTRADA

La primera marcación debe ser:

ENTRADA

Si todavía no existe Entrada, el sistema no deberá permitir:

SALIDA_ALMUERZO
REGRESO_ALMUERZO
SALIDA

14. REGLA DE SALIDA A ALMUERZO

Para poder registrar:

SALIDA_ALMUERZO

debe existir primero:

ENTRADA

del mismo trabajador y del mismo día.

Es decir:

ENTRADA ✓
↓
SALIDA_ALMUERZO ✓

Pero:

SIN ENTRADA
↓
SALIDA_ALMUERZO ✗

Mostrar:

No puede registrar salida a almuerzo porque aún no ha marcado su entrada.

15. REGLA DE REGRESO DE ALMUERZO

Para registrar:

REGRESO_ALMUERZO

debe existir previamente:

SALIDA_ALMUERZO

del mismo día.

Correcto:

ENTRADA
↓
SALIDA_ALMUERZO
↓
REGRESO_ALMUERZO

Incorrecto:

ENTRADA
↓
REGRESO_ALMUERZO

Mostrar:

No puede registrar regreso de almuerzo porque aún no ha marcado su salida a almuerzo.

16. REGLA DE SALIDA

Para registrar:

SALIDA

deberá existir:

ENTRADA

y, si el trabajador tiene horario de almuerzo asignado, también deberán haberse completado:

SALIDA_ALMUERZO
REGRESO_ALMUERZO

Secuencia normal:

ENTRADA
↓
SALIDA_ALMUERZO
↓
REGRESO_ALMUERZO
↓
SALIDA

No permitir:

SALIDA

sin:

ENTRADA

Mostrar:

No puede registrar salida porque no existe una entrada registrada para hoy.

17. EVITAR MARCACIONES DUPLICADAS

Un trabajador solamente puede tener una marcación de cada tipo durante la jornada normal.

Ejemplo:

Si Juan ya marcó:

ENTRADA
07:58

y vuelve a seleccionar Entrada:

No se puede registrar.

Ya existe una entrada registrada hoy a las 07:58 AM.

Debe existir una restricción única lógica basada en:

trabajador_id
fecha
tipo_marcacion

Además de la validación del backend.
